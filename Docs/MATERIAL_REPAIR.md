# Repair FBX material assignments in Unity 6.3 URP

The old scene builder compared imported material display names literally with the canonical names in `scene-data.json`. Thus `SipoSupermarket-SIPO_Chrome` missed `SIPO_Chrome` and silently retained its imported Standard material. The old validation accepted Standard because it only rejected missing materials and Unity's error shader.

## What the fix does

- Resolves exact canonical names first, then removes only the known `SipoSupermarket-` or `SipoMerchandise-` prefix. Names such as `brown.001` remain distinct. This includes the licensed merchandise materials, not only names beginning with `SIPO_`.
- Uses the original source identifiers from each ModelImporter's material table to persist external-object remaps to `Assets/Materials/*.mat`. Renderer display names are not used as importer keys.
- Reuses the existing URP/Lit assets without changing their colors, textures, transparency, metallic/smoothness, emission, keywords, render queue, names or instancing settings. Only missing materials are initialized from metadata during a full scene build. Repair requires the existing materials to be present.
- Checks serialized material snapshots before and after importer remapping. Any property change fails validation.
- Checks both importer remap tables, both imported FBX prefabs, and every environment MeshRenderer slot in the active scene, including inactive objects. Unknown/null materials, wrong asset references, wrong slot counts, empty slot arrays, missing model parts, and any shader other than `Universal Render Pipeline/Lit` are errors.
- Compares scene slots with their corresponding source-prefab slots, so a stale scene override cannot silently retain Standard. Repair replaces those material assignments and records prefab overrides.
- Validates before saving a regenerated scene. Updating the editor script does not automatically replace an existing generated scene even if its readiness marker is missing.

No FBX, Blender model, geometry metadata, texture image or gameplay script is changed by this commit. The repair command changes material import settings and assignments only. Unity writes the persistent remaps into the two FBX `.meta` files in your local project.

## Apply to your existing project

1. Save your work and close Unity. Back up `Assets`, `Packages` and `ProjectSettings`, including your existing `.mat`, `.unity` and `.meta` files. Commit local changes if you use Git.
2. From the project folder, run `git pull --ff-only origin main`. If you maintain a separate copy, replace **only** `Assets/Editor/SupermarketProject.cs` with the fixed file from this repository, retaining its existing `.meta`. All editor functionality for this fix is in that one C# file; the Python check is optional tooling.
3. Open the project in Unity **6000.3.26f1** with URP **17.3.0**, and wait for compilation/import to finish. Open your existing supermarket scene containing both connected FBX instances.
4. Select **Sipo → Repair active scene materials**. This remaps and reimports both FBXs, repairs their scene renderer assignments, and validates the result. It does not regenerate your layout or save the scene automatically.
5. Confirm the Console reports all three messages with no intervening exception:
   - `SIPO_MATERIAL_PROPERTIES_PRESERVED` — existing material snapshots are unchanged.
   - `SIPO_MATERIAL_VALIDATION_PASSED` — both FBX parts and all scene renderer slots passed. The supplied unmodified environment has **385 renderers**.
   - `SIPO_MATERIAL_REPAIR_PASSED` — the repair completed successfully.
6. Save the scene. Run **Sipo → Validate environment materials** again. For a persistence check, reimport both environment FBXs from the Project window, reopen the saved scene, and run that validation command once more.

Keep your correct `Assets/Materials` assets. Deleting or blanket-converting them is unnecessary. Inspect Chrome, Gold, Navy, glass, floor textures and emissive rings in Scene view after the assignment check passes.

If validation fails, the Console identifies the FBX/source material or renderer/slot. An unknown material fails instead of receiving a substitute. A missing or non-URP material asset must be restored at the reported path. If the model instances were unpacked or one part is missing, use a backed-up regeneration: the validator requires connected FBX instances to prove slot correspondence. A missing material can be generated by the scene builder; existing incompatible materials are deliberately rejected rather than overwritten.

## Safely regenerate the scene

1. Save your customized scene under a different name using **File → Save As**, for example `Assets/Scenes/SipoSupermarket_LocalBackup.unity`. Retain the project backup from above.
2. Select **Sipo → Build supermarket scene**. This replaces `Assets/Scenes/SipoSupermarket.unity` from the existing FBXs and metadata. It reuses your existing correct material assets. Scene-only placement/lighting customizations are not carried into the regenerated scene; your separately named backup retains them.
3. Confirm `SIPO_MATERIAL_PROPERTIES_PRESERVED`, `SIPO_MATERIAL_VALIDATION_PASSED`, `SIPO_VALIDATION_PASSED` and `SIPO_SCENE_READY` in the Console. Run **Sipo → Validate environment materials** on the saved scene as a final check.

The build does not save the regenerated scene when mapping validation fails. The in-place repair is sufficient if you want to preserve the current scene layout.

## Validation performed for this fix

The production C# resolver and slot-validation policy were compiled and executed directly against the material connections parsed from both actual binary FBXs:

| FBX | Mesh renderers | Material slots | Source material identifiers |
| --- | ---: | ---: | ---: |
| `SipoSupermarket.fbx` | 314 | 1,427 | 100 |
| `SipoMerchandise.fbx` | 71 | 749 | 115 |

**13,284 assertions passed.** These cover all 2,176 slots with canonical and both prefixed names, repeated resolution, exact-name precedence, numeric suffixes, unknown/missing names, incompatible shaders, and incorrect/missing asset-reference rejection. All project C# sources also compile against the real Unity 6000.3.26f1/URP assemblies. The [machine-readable result](MATERIAL_MAPPING_VALIDATION.json) records source and FBX hashes.

This is validated name/slot policy and API compilation, **not a successful native Unity import**. A native batch attempt exited **198**, reporting `No valid Unity Editor license found. Please activate your license.` The current cloud checkout has no locally generated `Assets/Materials` or populated `.unity` scene. Your local material snapshots, importer persistence, scene overrides and rendered appearance therefore still require the editor checks above; this report does not claim they ran on your machine.

Reproduce the offline regression and compilation with Blender plus the official editor's compiler/runtime installed:

```bash
python3 Tools/validate_material_mapping.py --editor /workspace/tools/unity/6000.3.26f1/Editor
python3 Tools/check_csharp.py --editor /workspace/tools/unity/6000.3.26f1/Editor
```

The regression extracts the production C# class from `SupermarketProject.cs`; it does not test a separate Python implementation. Intermediate inventories and executables stay in ignored `Artifacts/MaterialMapping/`.
